Cache or Denoise Less? Residual Reuse in a Flow-Matching World Action Model

6B Fast-WAM에서 2-step 무캐시 정책이 10-step의 LIBERO 성공률을 유지하며 지연을 202→92ms로 줄인 반면, 캐시는 sampler·noise 가정에 따라 63%까지 추락한다는 근거 기반 비판적 연구.

00 / ONE-MINUTE RECAP

핵심을 먼저 읽기

비교 기준선을 10-step에서 2-step으로 바꾸면 캐시의 의미가 달라진다. Flow-matching WAM에서 이전 제어주기 transformer 중간 출력(residual)을 재사용하는 캐시가 10-step보다 빠른 것은 사실이지만, 2-step 무캐시 정책이 거의 같은 성공률로 더 빠를 수도 있다. 성공/지연/캐시 경로 비율의 세 축을 함께 봐야 한다.

⌁ DEEP TECHNICAL REVIEW연구자용 상세 해설

연구 성격을 먼저 규정: 새 World-Action Model의 학습 논문이 아니라 이미 공개된 Fast-WAM의 residual-cache 최적화에 대한 재검증이다. Figure 1에서 x축은 평균 replanning call 지연, Figure 2에서 x축은 캐시된 flow path 비율이며 전혀 다른 실험을 나타낸다. 비열등성을 보고한 신뢰구간도 90%와 Wilson 95%를 혼동하면 안 된다.

01 / 문제 정의

연구가 풀려는 문제

로봇 VLA/WAM은 매 제어주기에 diffusion/flow denoiser를 여러 번 평가한다. 기존 C³ache는 10-step 원본을 기준으로 첫 8개 스텝의 행동 transformer residual을 재사용해 가속을 보고했다. 그러나 첫 2번 적분만으로도 원하는 행동을 거의 생성할 수 있다면 10-step cache의 점진적 최적화가 단순 K=2 baseline에 이기는지 알 수 없다. 또한 캐시가 '8단계를 건너뛰었다'는 숫자는 노이즈 시간표가 바뀔 때 flow 경로의 물리적 의미가 같지 않아 로봇에서 오래된 토큰이 제어를 망칠 수 있다.

02 / 핵심 기여

핵심 아이디어

Fast-WAM 자체를 새로 학습하지 않고 inference 최적화의 평가 기준선을 재설정한다. 1/2/4/10 Euler step을 캐시 없이 실행해 지연·성공률을 측정하고, 동일 Fast-WAM의 30-block action stack이 더한 residual R_k=h30−h0를 각 noise step에 저장한 후 다음 replanning 때 그대로 더하는 C³ache형 재사용과 맞비교한다. refresh 주기 τ와 sampler shift s, 고정/재추첨 시작 noise를 나눠 flow path 중 실제 재사용되는 몫 1−σ_m와 성공률 관계를 검사한다. Figure1은 SR–latency 파레토, Figure2는 flow coverage별 캐시 취약성 분석이다.

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

기존 C³ache는 10step 원본 정책 대비 캐시로 많은 transformer pass를 생략하는 방향을 강조한다. 이 논문은 이미 2step 실행으로 같은 성공률이 나온다면 캐시 자체가 가장 유리한 비용-품질 조합이 아닐 수 있음을 보인다. action expert residual reuse, sampler shift와 초기 noise 규칙을 함께 적시하도록 요구하며 더 적은 step이라는 평범한 baseline을 강력한 반례로 사용한다. 높은 시뮬레이션 성공률만으로 실제 임베디드 지연 개선을 단정하지 않는다.

03 / 설계와 학습

방법론 · 아키텍처

Fast-WAM은 5B video expert+1B action expert로 두 카메라 입력을 한 번 인코딩하고 영상 KV context를 얻는다. 이후 30-block action transformer가 32개 미래 action chunk를 noise σ=1에서 σ=0까지 Euler K단계 적분하며 20Hz 로봇은 그중 10개(0.5초)를 사용한다. sigma_k=s*u_k/(1+(s−1)*u_k), u_k=1−k/K이고 original checkpoint는 s=5, Optional-IDM은 s=1로 기본 제공된다. refresh cycle에서 30-layer 전체 입력 h0·출력 h30 차이 R_k를 저장해 후속 같은 k step에서 h0+R_k로 재사용하고 나머지 단계는 full forward를 수행한다. τ=2/4/8/never, cache0–7/10, attenuation, first-step partial caching, 신선 노이즈와 서로 다른 shift를 교차한다. LIBERO-Goal 10과제×10초기상태, 전체 검정 500초기상태, shift 검정 50초기상태, RTX A6000 개별 프로세스 환경에서 CUDA synchronized call time(초기 compile 제외)을 측정했다(§2–4, Appendix A).

DEEP DIVE / 01

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    Fast-WAM의 관측·영상 context 구축

    두 카메라 관측을 인코딩하고 5B video expert가 동작 생성을 조건화할 KV context를 한 번 생성한다. 재계획마다 이 작업은 생략되지 않는다.

    2 images → video KV memory
  2. 02

    행동 expert의 K단계 Euler 적분

    30-block 1B action expert가 시작 noise에서 32 future actions를 생성한다. 실행기는 20Hz에서 앞 10개만 수행하고 다시 관측한다.

    σ=1 → K=1/2/4/10 Euler steps → σ=0
  3. 03

    refresh 호출에서 residual 저장

    10step 전체를 계산할 때 각 step의 transformer 입력 h0와 출력 h30의 차이 R_k=h30−h0를 저장한다. 같은 k의 residual이 다음 제어 주기에 존재한다.

    R_k(step k)=h30−h0
  4. 04

    reuse 호출에서 중간계산 대체

    cache된 noise step에서는 30-block 전체를 건너뛰고 h0+R_k로 복원, 뒤쪽 미캐시 step은 다시 계산한다. 첫 호출과 매 τ번째 호출에는 cache를 새로 갱신한다.

    (K,m,τ)→reused/fresh expert passes
  5. 05

    sampler shift와 noise 시드 교차

    s1/3/5와 fresh/fixed latent를 나눠 최초 m step이 실제 noise-to-action flow path의 1−σ_m 만큼을 차지하는지 측정한다.

    m=8,K=10 → path share 80% (s1), 44%(s5)
  6. 06

    같은 평가구간에서 성능·지연·불확실성 측정

    LIBERO-Goal 100 또는 shift/noise 50상태를 구성별 독립 프로세스로 실행하고 RTX A6000 synchronized ms와 성공을 기록. 500상태·카메라 지터로 비열등성 보강.

    matched SR / mean,p95 ms / CI
DEEP DIVE / 02

핵심 설계·학습 신호 해설

왜 두 fresh step을 유지하는 캐시는 2-step uncached보다 빨라지기 어려운가

영상 인코딩·video expert와 마지막 두 step을 그대로 계산한다면 다른 앞단의 캐시를 만들고 읽어오는 overhead가 남는다. 새로 계산할 때 두 단계면 충분한 시나리오에서는 cache 이득이 원천적으로 좁다.

단계 개수보다 integration path coverage

s1은 초기 8/10 step이 경로 80%를, s5는 44%를 담당한다. 실제 flow vector field를 크게 건너뛴 채 stale residual을 재사용하면 선택한 최종 행동이 달라질 수 있다.

고정 latent와 새 noise의 차이

Fast-WAM은 주기마다 동일 latent를 사용한다. noise를 재추첨하면 초기 action token이 다른 지점에서 시작해 이전 호출의 residual과 정합성이 떨어진다. 60%+ coverage에서 14–40pp 성공 손실이 이를 드러낸다.

05 / 비판적 해석

한계와 비판적 검토

벤치마크는 실물 로봇이 아니라 LIBERO 시뮬레이션이다. 대개 10작업×10 상태 또는 5상태, 한 6B 구조, 두 checkpoint, 거의 하나의 noise seed, 한 RTX A6000 기기라는 좁은 조건이다. 500상태의 비열등 검정도 전체 WAM 일반화가 아니라 Optional-IDM 한 모델의 2 vs 10-step 조건이다. 지연값은 한 호출 CUDA 동기화 지연으로 20Hz 실제 제어·보정/재계획 staleness, GPU memory 및 energy를 측정한 것은 아니다. s=5 original과 s=1 Optional-IDM은 checkpoint와 sampler가 함께 다른 비교이므로 Figure2 교차 실험을 함께 봐야 한다. 50상태에서 캐시 flow coverage가 64% 이하면 성능이 유지된 듯 보인다는 관찰은 보편적인 안전 경계가 아니다. 초반 refresh 때의 큰 시간도 평균과 p95에 다르게 나타난다.

비교군·Ablation

[편집 제안] 2step 무캐시, 10step 무캐시, C³ache, residual attenuation, 첫 step 캐시/나머지 1step fresh, CUDA Graph on/off, 동일 path-share cache.

기록할 지표

[편집 제안] task-level SR, noise별 paired CI, noninferiority 마진2/5pp, p50/p95 call latency, first refresh overhead, GPU peak VRAM/energy, 20Hz stale controls.

실패 해석·주의점

[편집 제안] cache 초기화와 지연을 부하 동등 조건으로 측정하고 한 시드·50상태의 64% 경로 관찰을 안전 보장으로 외삽하지 않는다.
