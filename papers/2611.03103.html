VLALagBench: Understanding When and Why VLA Inference Latency Matters

VLALagBench는 움직이는 목표물에서 VLA 추론 지연의 피해가 작업 정밀도와 실행 모드에 따라 달라지는 이유를 분석한다. 0.1m/s에서 100ms 지연은 set-down 71.5%→40.5%였으나 grasp는 86.5%→74.0%였고, 비동기 모드 역시 정책별로 이득이 다르다.

00 / ONE-MINUTE RECAP

핵심을 먼저 읽기

VLA ‘한 번의 추론이 몇 ms 걸리는가’보다 중요한 것은 그 시간에 물체가 얼마나 이동하며 로봇이 어떤 이전 action을 실행하고 있는가이다. VLALagBench는 동적 목표물, 정책, sync/lazy async/continuous async 모드를 교차해 작업별 성공률 민감도와 실용적인 배포 모드를 분석한다. (§3–5)

01 / 문제 정의

연구가 풀려는 문제

정지한 컵 위로 그리퍼를 내리는 경우와 컨베이어 위를 움직이는 작은 접시에 그릇을 내려놓는 경우에 모두 ‘100ms는 느리다’라는 기준을 적용하는 것은 부정확하다. 시각 관측 이후 100ms가 흐르면 0.1m/s 목표는 1cm 이동하고, placement tolerance가 3cm라면 오차 예산의 1/3이 사라질 수 있다. 모션이 거의 없는 기존 LIBERO 성능과 서버의 tokens/s만으로 실제 동적 조작 신뢰성을 예측하기 어렵다. 논문은 task·speed·latency·policy·execution mode를 분해한다. (§1–2, Figure 1)

02 / 핵심 기여

핵심 아이디어

‘지연’은 추론시간이라는 단일 숫자가 아니라 (a) 정책이 보고 있는 장면의 오래됨(observation staleness)과 (b) 새 action을 기다리며 로봇이 멈춰 있는 시간(idle)을 만든다. sync는 추론 중 마지막 pose를 유지해 지연에 취약하나 action sequence는 정렬된다. lazy async는 현재 chunk를 실행하는 사이 새 추론을 시작하므로 대기시간을 줄이지만 오래된 관측으로 만든 action의 앞부분을 버릴 수 있다. continuous async는 더 자주 관측/생성을 요청해 최신성을 올릴 수 있으나 계산 부담과 chunk 교체의 위험을 낳는다. 단일 최선 모드는 없고 tasks마다 장단이 다르다. (§3.5, Figure 1)

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

기존 LIBERO/RoboCasa는 시연 학습·일반화에 집중하며 환경이 거의 정적이다. 로봇 inference 최적화 연구는 ms/Hz 또는 throughput을 측정하지만 그 수치가 동적 task success로 어떻게 연결되는지 명확하지 않다. VLALagBench는 그 사이를 policy-level success로 연결하고, async 실행을 실제 조작 행동시간선의 문제로 평가한다. 정책을 개선한 신모델이라기보다 시스템 선택 기준의 논문으로 읽는 것이 정확하다.

03 / 설계와 학습

방법론 · 아키텍처

§3.2의 4개 primary tasks는 release(움직이는 바구니), set-down(움직이는 판 위 그릇), grasp(움직이는 물체), articulated(움직이는 서랍 손잡이)이며 Figure 4는 실제 타깃 이동 경로를 표시한다. MuJoCo를 기반으로 target speed, latency 0–250ms/50ms간격을 주입하고 3 policies(π0.5, GR00T N1.7, MolmoAct2)를 비교한다. 기본 제어주기 20Hz=50ms, 실행 horizon H=5, chunk size K=10(π0.5/MolmoAct2) 또는 K=16(GR00T)이다. Sync는 추론 중 마지막 팔 pose/그리퍼 유지, lazy는 구 chunk를 이어 실행하며 도착한 새 chunk의 앞 L개 action을 건너뛰고, continuous는 최대한 겹쳐 요청한다. 동일 조건 200 rollout, 성공 전 최대 600 executed steps의 예산과 stall 보정 규칙을 쓴다(§4.1, Appendix B/C). §5는 학습 목표가 아니라 (staleness, idle)의 경험적 sensitivity 계수를 소량 calibration 성공률로 맞춰 unseen latency의 성공률/모드를 예측한다. 궤적 예측 모델의 성공 보장이나 이론적 안전 증명은 아니다.

DEEP DIVE / 01

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    01 | 로봇 제어시간과 VLA 응답을 분리

    20Hz 제어에서 매 tick은 50ms다. 이때 정책의 영상 관측과 action chunk가 생성되는 사이 L개의 tick이 지나면 관측 기준 환경이 이동한다. 명목상 모델 추론속도와 task success를 구분한다.

    20Hz; injected latency 0,50,100,150,200,250ms
  2. 02

    02 | 4가지 접촉 상황을 동일 규칙으로 설계

    정적 물체를 움직이는 용기에 놓기(release), 움직이는 판에 내려놓기(set-down), 움직이는 물체 집기(grasp), 움직이는 서랍 손잡이 조작(articulated)을 설계하고 표적 속도/경로를 통제한다. 성공 조건의 공간적 허용오차가 민감도를 결정한다.

    task × target speed × checkpoint
  3. 03

    03 | 세 execution modes의 요청·실행 시간선 정의

    sync는 새 추론 동안 마지막 로봇 명령 유지; lazy async는 이전 chunk를 이어 실행하고 stale된 새 chunk prefix를 건너뜀; continuous async는 가능한 자주 새 관측으로 inference를 시작해 새 chunk로 교체한다. 비동기라고 항상 빠르거나 더 신선한 것은 아니다.

    sync / lazy async / continuous async
  4. 04

    04 | latency를 주입하고 조건별 시행 수를 고정

    §4.1과 Appendix B의 200 evaluation rollouts/condition, 600 executed steps budget, inference stall 처리 규칙을 지켜 strict success를 기록한다. 기존 LIBERO 정적 과제의 episode 길이와 구분한다.

    task×latency×mode×policy, 200 trials/condition
  5. 05

    05 | 성공률을 staleness·idle에 대응

    모드마다 관측이 낡아지는 tick 수와 기다림을 analytic proxy로 나타낸다. sync/lazy의 평균 staleness는 (H−1)/2+L, continuous의 proxy는 (3L−1)/2. 이 관계를 이용해 task/policy별 empirical sensitivity 계수를 소수 지연 조건에서 fit한다.

    staleness & idle time → fitted success prediction
  6. 06

    06 | 보지 않은 지연에서 모드 고르기

    zero/100/200ms 등 제한 calibration에서 학습된 모델로 50/150/250ms의 성공률을 예측하고 선택한다. 지연이 고정돼 있지 않은 실제 시스템에 적용하려면 p95 latency, queue contention, 재초기화 정책까지 따로 보정해야 한다.

    small calibration → predicted SR(mode,L) → deployment configuration
DEEP DIVE / 02

핵심 설계·학습 신호 해설

빠른 손과 ‘오래된 눈’의 절충

움직이는 타깃을 추적할 때 추론 중 멈춤을 없애면 idle은 줄지만 현재 action이 이전 영상의 target position을 추종할 수 있다. 목표 위치 오차 tolerance가 작은 set-down은 중단 없이 움직여도 stale action이 충돌하거나 놓치게 한다.

읽기 포인트§3.5 mode timing, §4.2 Figure 6

왜 policies 사이에 비동기 개선 폭이 다른가

π0.5/MolmoAct2/GR00T은 chunk 길이와 정책의 폐루프 반응성, 외란에 대한 보정 능력이 다르다. 200ms release 사례에서 lazy async는 π0.5 +33pp, MolmoAct2 +35pp지만 GR00T +2pp다. 모든 VLA가 async에 적합하다는 결론은 실험으로 지지되지 않는다.

04 / 근거와 결과

실험과 주요 발견

✳

동적 목표 speed=0.1m/s에서 latency 100ms로 바뀌면 set-down strict success 71.5→40.5%, grasp 86.5→74.0%(§4.2/Figure 6)로 동일 모델 지연의 영향이 과제마다 다르다. speed=0.1m/s, 200ms, release에서 sync→lazy async 전환 시 π0.5 48.5→81.5%, MolmoAct2 57.0→92.0%이나 GR00T N1.7은 30→32%만 개선되고, set-down에서는 GR00T의 비동기 모드가 불리할 수 있다(§4.3/Figure 9). Table 1의 거의 정적인 speed=0.001m/s 환경에서 π0.5는 release 93.0, set-down 93.5, grasp 98.5, articulated 94.5%다; 단순한 원 LIBERO checkpoint 성공률로 둔갑시켜서는 안 된다. §5/Appendix D의 제한된 calibration으로 예측한 π0.5의 보간 지연 성공률 RMS 오차 약 5.7 percentage points. 이는 학습한 수식이 보편적 물리법칙이라는 뜻이 아니라 해당 benchmark, policies 및 calibration 범위에서 확인한 경험값이다.

05 / 비판적 해석

한계와 비판적 검토

실험 주력은 MuJoCo에서 목표 경로를 인위적으로 움직이고 latency를 주입한 시뮬레이션이므로 실제 GPU 큐잉·카메라 지연·패킷 손실·동작 controller drift를 완전 재현하지 않는다. 600-step budget과 stall 보정은 기존 LIBERO의 220–300-step 평가와 다르다. 200 rollouts/condition이라도 시뮬레이터 초기 상태와 탐색 경로에 결과가 의존한다. Appendix E의 Isaac Sim DynamicVLA는 별도 정책·컨트롤 설정이고, Appendix F의 SO-101 실물은 MolmoAct2 중심이라 전체 3모델의 실물 일반화로 읽으면 안 된다. 회귀 계수가 정책·작업에 따라 음수가 되는 경우가 있어 fitted model에 인과적 보편성을 부여할 수 없다.
