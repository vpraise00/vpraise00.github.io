RoboCasa: Large-Scale Simulation of Everyday Tasks for Generalist Robots

RoboCasa는 10개 주방 평면×12개 스타일의 120장면, 2,509개 3D 자산, 25 atomic+75 composite 작업과 10만여 합성 시연으로 로봇 데이터 확장을 시험한다. 생성 시연 수별 성공률, 어려운 복합작업, Franka 실물 Real-only 대비 Real+Sim을 공식 HTML·부록 Figure/Table과 함께 분석한다.

00 / ONE-MINUTE RECAP

핵심을 먼저 읽기

로봇 학습 데이터 확장은 이미지 배경을 늘리는 일만이 아니다. RoboCasa는 실제 기구가 열리고 닫히는 물리 환경, 작업 계층, 인간 시연의 object-centric 재배열, 합성 궤적의 성공 필터를 결합한다. 그러나 10만 시연에도 일부 장기 작업 성공률은 0%다.

⌁ DEEP TECHNICAL REVIEW연구자용 상세 해설

시뮬레이터의 공헌을 모델의 SOTA로 착각하지 않는 것이 중요하다. RoboCasa는 더 다양한 관측과 행동을 만드는 데이터·벤치마크 인프라 논문이다. 공간/객체/언어/작업 순서의 다양성을 동시에 제공하고, 100k trajectory와 실제 로봇 실험으로 그 가치와 실패를 모두 보고한다.

01 / 문제 정의

연구가 풀려는 문제

실물 로봇에게 '찬장에서 컵을 꺼내 커피머신에 놓고 버튼을 눌러'를 가르치려면 많은 장소·조명·기물·물체와 긴 작업 순서를 경험해야 한다. 실제 집 수백 개와 로봇 운영자를 모집해 수만 개 시연을 모으기는 어렵다. 기존 시뮬레이터는 장면/물체/실행 가능한 주방 조작이 부족하고, 언어모델이 작업을 제안하더라도 로봇이 실제 수행할 성공 판정과 물리 구현은 사람이 검토해야 한다. RoboCasa는 '무엇을 얼마만큼 다양하게 합성해야 실물로 전이하는가'라는 플랫폼/데이터 연구 문제다.

02 / 핵심 기여

핵심 아이디어

RoboCasa는 MuJoCo/robosuite 물리 위에 10 kitchen layouts×12 design styles로 120 scenes, 2,509 3D object assets(153 categories, 그중1,592 Luma.ai)와 생성형 텍스처를 구성한다. 25 atomic tasks는 파지·문·서랍·손잡이·노브·버튼·삽입·이동의 8기술, 75 composite tasks는 20 kitchen activities를 LLM으로 초안 작성한 뒤 연구자가 논리 오류를 걸러 직접 구현한다. 4명의 인간 조작자가 SpaceMouse로 각 atomic task당 50 demonstrations(총1,250)를 수집하고 MimicGen이 object-centric segment를 새로운 배치에 맞춰 변환해 자동 시연을 만든다. 편집 포인트는 'GPT가 코드를 자동 작성했다'가 아니라 사람이 유효한 과제와 데이터 생성을 검수했다는 사실이다.

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

실세계 DROID(2403.12945)는 여러 실제 환경의 시연을 모아 다양성을 확보한다. RoboCasa는 유사한 목표를 시뮬레이션 scene/object/language/task 변동과 MimicGen rollout으로 보완한다. 그러나 동일한 물리 오차와 촉각을 재현했다는 뜻이 아니며 Real+Sim 24.4% 평균은 아직 실물 조작의 높은 reliability라 보기 어렵다.

03 / 설계와 학습

방법론 · 아키텍처

§III–IV 및 Appendix VII–IX를 따라 ① 주방 layout/style/fixture/texture로 scene 표본공간 생성, ② Objaverse/Luma의 물체와 articulated appliances를 MJCF로 변환해 Door/knob/state change 구현, ③ 원자 작업 25개와 human-screened LLM composite 75개 작성, ④ operator 4인이 25×50=1,250 teleop seed trajectories 수집, ⑤ MimicGen이 객체 기준 조작 구간을 추출·새 object pose에 맞춰 warp/stitch하고 실제 simulated rollout으로 성패 검증, ⑥ 24 atomic(task navigation 제외) ×100/300/3,000 = 2,400/7,200/72,000 synthetic datasets를 만들어 BC-Transformer 학습, 복합작업 pretrain→50-human fine-tune, 실물 Franka Real+Sim co-training 평가. Release는 생성 물체 데이터 28K를 추가해 총100K scale이다. Appendix IX의 BC Transformer는 지난10 observations+language CLIP, image 3views ResNet18+FiLM, 6층 약20M trainable, 다음10 actions 산출 후 첫 행동만 실행하고 재계획; 500k steps LR1e−4이다.

DEEP DIVE / 01

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    10 layout×12 style 주방 장면과 물리적 fixture 만들기

    MuJoCo/robosuite의 물리 장면에 각 주방 평면과 디자인 스타일을 조합해 120장면을 구축한다. 도어·서랍·노브는 관절을 갖춘 MJCF 객체로, 색/재질은 MidJourney 텍스처로 변동시켜 관측의 외형 변화를 만든다.

    layout × style × randomized texture → kitchen scene
  2. 02

    2,509개 물체와 사용 가능한 interactive appliances 보강

    Objaverse와 Luma.ai에서 153개 범주 중 2,509개 물체를 품질 필터로 선정하고, 그중 1,592개는 Luma.ai에서 가져온다. 단순 이미지 생성과 달리 집거나 회전시킬 수 있는 물리 모델이 필요하므로 microwave door/stove knob 등 joint와 상태 변환을 구현한다.

    assets → MJCF + graspable/articulated semantics
  3. 03

    25개 원자 작업 및 75개 복합 작업을 검수해 구현

    8종 기본 운동 기술에 해당하는 atomic 25개를 정의한다. GPT-4/Gemini 1.5로 20 kitchen activities에서 복합작업 초안을 얻되 blender가 없는 주방에서 blender를 요구하는 오류처럼 현실성 없는 제안은 사람이 걸러내고 75개 블루프린트의 실행 로직을 코딩한다.

    skills + LLM draft + human review → executable tasks
  4. 04

    SpaceMouse 원본 시연을 object-centric 동작 세그먼트로 변환

    4명의 operator가 atomic마다50개 시연을 만든다. MimicGen은 object-centric segment를 잘라 다른 scene/object pose에 맞춰 좌표를 바꾸고 이어 붙인다. 실제 simulated replay로 성공을 확인한 합성 시연만 dataset에 남긴다.

    1,250 human seeds → MimicGen transforms + simulation rollouts
  5. 05

    2.4K/7.2K/72K 데이터 크기별 BC-Transformer 정책 학습

    각 24개 atomic non-navigation tasks에 대해100/300/3000개의 generated data를 구성한다. BC-Transformer는 observation 10개, 3 camera, CLIP text와 6층 Transformer(약20M)로 다음10 actions를 학습하며 첫 action만 실행한 후 관측해 replanning한다. 비교를 위해 학습 texture와 평가 texture를 분리한다.

    generated demonstrations → BC-Transformer → closed-loop action
  6. 06

    장기 복합작업과 실제 Franka에 동일 데이터 원리 적용

    복합작업 5개는 atomic-pretrained policy의 50-demo finetune을 scratch와 비교한다. 실물은 DROID 기반 Franka에서 각 과제50 real demonstrations를 모두 확보한 상태로, real-only와 real+all synthetic co-training을 비교한다. sim OSC20Hz와 real15Hz 제어 차이를 인정한다.

    atomic pretrain → composite finetune; real demos + sim demos
DEEP DIVE / 02

핵심 설계·학습 신호 해설

자동 생성은 실패 실험도 포함하는 물리 rollout 과정

원 시연을 객체 중심 구간으로 분할해 신규 object poses에 좌표 변환한 다음 시뮬레이션으로 재생해 성공한 rollout을 수집한다. 이는 단순 색상 증강이나 기존 시연 복제와 다르지만, 성공 체크가 충돌 없는 자연스런 행동을 의미하지는 않는다.

읽기 포인트§IV-C MimicGen / §VI limitations

LLM이 만드는 것은 executable source 전체가 아니라 검토가 필요한 blueprint

예를 들어 존재하지 않는 blender 사용이나 식기류에 맞지 않는 gripper skill을 제안할 수 있다. 논문은 task blueprint을 사람이 필터/수정하고 75개를 구현했다고 적는다. 따라서 '100 tasks fully automatic'이라고 부르면 사실과 다르다.

05 / 비판적 해석

한계와 비판적 검토

RoboCasa의 생성형 객체와 텍스처가 새 환경 다양성을 주지만 일상 전체의 고충실도를 보장하지 않는다. 논문 스스로 합성 시연에 급격한 움직임·충돌이 남는다고 인정한다. 10만 synthetic trajectories ≠ 10만 개 독립 인간 조작 시연; 대부분은 MimicGen 기존 segment 재사용이다. 75개 복합작업을 LLM이 완전 자동 생성/코딩했다는 것도 사실이 아니다. 5개 composite task만 실제 정책 실험했으며 최종 성공률은 PrepareCoffee 0% 등 낮다. 실물 Real+Sim은 각 과제별 50 real demos를 사용했으므로 ‘시뮬만 학습하여 실물 제로샷 성공’으로 표현할 수 없다. 실물 setup/제어주파수/카메라 calibration이 달라 domain gap가 남는다. Appendix Diffusion Policy 12 vs BC56은 입력 history가 달라 apples-to-apples architecture ablation이 아니다. 부록 시뮬레이터 RTX A5000·CPU 관측 속도는 성능과 안전 보증이 아니다.

RESEARCH LAB / EDITORIAL PROPOSAL

내 연구에 적용한다면?

아래는 논문 저자의 검증 결과가 아니라, 논문에서 출발해 설계한 **후속 실험 제안**입니다.

검증 가설

[편집 제안] 실물 전이의 이득은 합성 수량보다 대상 객체 형태와 카메라/텍스처 다양성에 민감하며, 불안정한 MimicGen 궤적을 무조건 늘리면 특정 기술에서 역효과가 날 수 있다.

구체적 실험 설계

[편집 제안] RoboCasa에서 24 tasks의 장면 다양성 10/50/120, 객체 범주 10/50/153, texture augment on/off를 같은 7200 trajectories/총 gradient steps로 통제한다. 실물에는 counter→sink/counter→cabinet 등 3과제, 50 real demos/task 공통, 각 seen/unseen cat≥30 trials×3 seed를 수집한다.

비교군·Ablation

[편집 제안] real-only, sim-only(별도 평가), real+random-sim, real+object-matched-sim, real+quality-filtered-sim; BC-Transformer와 Diffusion Policy를 history/action horizon 등 동일한 인풋으로 맞춰 비교.

기록할 지표

[편집 제안] strict episode SR/성공 WilsonCI, 특정 skill SR(파지, 접촉, 문 조작), 궤적 jerk/물리 충돌, scene-style OOD gap, training GPU cost, real sensor sync/control lag.

실패 해석·주의점

[편집 제안] 생략한 tactile physics와 충돌 위험 때문에 sim policy를 실물에 직접 돌리기 전에 제한 속도/soft stop/작업 공간 안전구역을 정의한다. 100K trajectories의 독립성 및 human dataset 1,250 차이를 투명하게 보고.
