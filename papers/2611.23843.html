00 / ONE-MINUTE RECAP

핵심을 먼저 읽기

하위 작업 실행 중 무엇이 실패했는지 알아차려야 장기 조작이 이어진다. RePlan-VLA는 계획자/학습된 progress monitor/동결된 VLA executor를 분리하고, 관측된 오류 설명을 입력으로 남은 계획을 갱신한다. 행동 정책 자체를 재훈련하지 않되 progress estimator는 별도 LoRA 학습한다.

⌁ DEEP TECHNICAL REVIEW연구자용 상세 해설

이 프레임워크에서 학습하지 않는 것과 학습하는 것을 구분해야 한다. 행동 정책 πΦ는 frozen이지만 별도 진행률 모델 FΘ는 지도 학습으로 적응한다. Figure 2는 계획자–행동자–감시자–재계획자의 순환 흐름을, Figure 1은 단일 실물 복구 사례를 보여준다. RoboCasa/CALVIN 성공률은 서로 다른 분모와 성공 정의를 갖는다.

01 / 문제 정의

연구가 풀려는 문제

한 번에 '서랍 열기→컵 집기→옮기기'를 명령하면 첫 서랍 열기가 충분히 완료되지 않았는데 둘째 단계로 넘어가 이후 순서가 실패한다. 단일 VLA가 명령 해석, 환경 기억, 긴 동작, 진행률 감시, 오류 복구까지 모두 담당하면 왜 실패했는지 확인하기 어렵다. 단순 시간 기반 monotonic progress는 물체를 잘못 잡거나 이미 놓은 물체가 떨어지는 실제 상황을 반영하기 힘들다. 저자는 실행 상태에 맞춘 closed-loop 고수준 관리가 별도 필요하다고 주장한다.

02 / 핵심 기여

핵심 아이디어

Few-shot VLM planner DΨ는 장기 지시를 각종 관측·물체 bounding box와 함께 해석하여 짧은 subtask와 go_to/move_to primitive로 나눈다. 별도 verifier가 각 하위 지시가 현재 frozen VLA가 알아들을 문장인지 확인한다. VLA πΦ가 현재 작업의 action chunk를 실행하는 동안 progress estimator FΘ는 최근 영상과 primitive을 평가해 수치 진행률 p, 재계획 이진 신호 r, 자연어 오류 설명 E를 만든다. 성공한 subtask는 기록 η에 남기고 실패한 subtask는 현재 장면+원래 명령+완료 이력+오류 설명으로 다시 계획한다. Figure1의 흰 블록 재시도, Figure2의 잼병 잘못 접근 후 회복은 이 루프의 질적 예시다.

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

단일 VLA가 모든 메모리와 진행률을 동시에 학습하도록 확장하는 경향과 달리 RePlan은 executor를 그대로 두고 외부 VLM을 붙여 실패 피드백을 다음 지시로 바꾼다. 단순 future observation predictive 방법과 달리 현재 어떤 primitive가 완수됐는지 관측해 다음을 바꾼다. 다만 동작 이전 확률 분포와 low-level 안전성은 바꾸지 못하며 monitor/grounding의 별도 비용이 든다.

03 / 설계와 학습

방법론 · 아키텍처

프레임워크는 ① Qwen3-VL-8B few-shot planner가 scene annotated visual input을 받아 subtask와 원시 조작(go_to=접근·집기, move_to=운반·놓기) 생성, ② LLM verifier가 Awomo-0.5I executor의 언어 인터페이스에 맞게 필요시 subtask 재작성, ③ 고정 VLA가 현재 단계를 실행, ④ 다른 Qwen3-VL-8B 기반 progress network가 매 μ=50 환경 스텝마다 10스텝 간격 5개 프레임을 읽고 go_to/move_to 진척도를 판정, ⑤ go_to threshold 0.80/move_to threshold 0.65로 완료를 결정하며 정체·예상치 못한 결과에는 r=1과 E를 내보내 남은 행동 chunk를 폐기, ⑥ planner가 completed-history를 보존해 실패 원인에 맞게 남은 절차를 생성하는 순서다. progress model은 LoRA r16 α32+1024차원 prediction head를 단일 H100에서 80,000 steps, effective batch8, LR(LoRA)1e−5/head1e−4로 미세조정했다(§4.1). 기본 executor는 benchmark별로 사전 fine-tune되어 있으나 RePlan 수행 중에는 동결이다.

DEEP DIVE / 01

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    객체 위치 표시로 scene grounding

    원래 RGB observation에 SAM3가 찾은 목적 물체의 label과 bounding box를 올려 Qwen3-VL planner가 '무엇이 어디 있는지' 언어와 영상에서 함께 확인한다.

    o_t + detected object labels/boxes → õ_t
  2. 02

    장기 지시를 subtask와 primitive로 분할

    few-shot Qwen3-VL-8B planner가 장기 명령을 짧은 지시 시퀀스로 바꾼다. 각 단계의 기본 primitive는 go_to(접근·파지), move_to(물체 운반·놓기)이다.

    L + õ_t → S1…SK and primitive sequence
  3. 03

    Instruction verifier로 executor 친화적 언어 확인

    별도 verifier가 생성 subtask 문장을 frozen VLA가 학습 중 접한 표현 방식과 일치하는지 검사하고 문장이 어색하면 planner에게 수정을 요구한다.

    subtask S → verify / rewrite
  4. 04

    Frozen VLA executor로 한 subtask 실행

    사전 fine-tune된 Awomo-0.5I가 현재 observation과 한 subtask 문장으로 chunk 행동을 예측해 실행한다. 장기 기억은 이 모델 내부에 넣지 않는다.

    πΦ(o_t, S_k) → action chunk
  5. 05

    진행률·실패·원인 설명 세 출력 동시 산출

    50 환경스텝마다 10step 간격 5개 영상으로 현재 primitive의 completion p, 실패 재계획 신호 r, 자연어 실패 설명 E를 생성. go_to 0.8, move_to 0.65의 문턱을 따로 사용한다.

    frames+task+history → p, r∈{0,1}, E
  6. 06

    완료 이력 보존·남은 순서 재계획

    실패라면 오래된 action chunk의 미실행 부분을 버리고 원지시, 성공/실패 history, 최신 observation, 실패 원인 E를 planner에 넘긴다. 이미 성공한 하위목표는 불필요하게 반복하지 않도록 기록한다.

    (L, õ_t, η, failed S, E) → revised remaining plan

05 / 비판적 해석

한계와 비판적 검토

'추가 fine-tune이 없다'는 설명은 VLA executor의 가중치에만 해당하며 progress estimator에는 H100에서 80,000 스텝 별도 SFT가 필요하다. Qwen3-VL planner/estimator는 8B이므로 경량 edge latency나 GPU 비용 자료 없이 저렴한 배포라고 말할 수 없다. CALVIN harD 평가 기준 본문에 100/50 sequences 상충이 존재하고 해당 PDF/HTML에는 저자가 반복 참조한 독립 Appendix가 제공되지 않아 프롬프트, 데이터 주석 및 구현에 관한 일부 근거는 확인할 수 없다. RoboCasa split은 각80회로 성공률 몇 개 pp의 차이는 trial 변동에 민감하다. Table1의 baseline 사전학습·센서/언어 interface와 VLA의 제어기는 서로 다를 수 있다. progress monitor의 50-step 호출 간격은 중간 위해행동·목표취소를 놓칠 수 있으며, 실물 사례에서 사진을 N-episode 통계로 환산하면 안 된다.

RESEARCH LAB / EDITORIAL PROPOSAL

내 연구에 적용한다면?

아래는 논문 저자의 검증 결과가 아니라, 논문에서 출발해 설계한 **후속 실험 제안**입니다.

검증 가설

[편집 제안] 장기 실행 향상의 대부분은 독립적인 진행률·실패 신호의 신뢰도에서 비롯되며, 실행자 재학습보다 monitor calibration이 더 효율적인 접근일 수 있다.

구체적 실험 설계

[편집 제안] RoboCasa365 32개 작업에서 동일 pretrained Awomo policy를 고정하고 progress interval 10/25/50/100step 및 threshold .6~.9를 sweep한다. CALVIN harD 실제 50/100 subset ID를 우선 확인하고 평가, Franka 실물 각 시퀀스≥30회 strict success를 기록한다.

비교군·Ablation

[편집 제안] Frozen executor only, planner-only, verifier-only, progress + task history, trained-vs-zero-shot monitor, oracle completion predicate, no failure text, SAM3 bounding boxes vs masks.

기록할 지표

[편집 제안] strict episode SR/연속작업 길이, per-primitive done precision/recall, error diagnosis F1, false replan rate, end-to-end replanning latency, physical collision/safety stops, confidence intervals.

실패 해석·주의점

[편집 제안] 공식 Appendix 부재 상태에서 세부 프롬프트·annotation을 임의 재구성하지 않는다. CALVIN 50/100 분모 모순 해결 전 p-value를 계산하지 않고 프랑카 실물은 별도 안전 회로로 감시한다.
