RoboSeed: Multidimensional Evaluation of Vision-Language-Action and World-Action Models

RoboSeed는 새로운 VLA의 성공률 경쟁이 아니라 정책 선택의 재현 가능한 평가 체계를 제안합니다. 작업 성공률, 학습비, 배포비, 연구 근거, 재현성을 다섯 축으로 나누고 RoboTwin 실측 및 Appendix Table의 조건·빈 측정치를 검토합니다.

00 / ONE-MINUTE RECAP

핵심을 먼저 읽기

RoboSeed는 '가장 좋은 VLA'를 뽑은 논문이 아닙니다. 작업 성공률이 높아도 학습비와 서빙비, 평가 프로토콜, 공개 증거가 부족하면 모델 선택에 필요한 결론을 보류해야 한다고 주장합니다. (PDF §1, §5, Table26)

⌁ DEEP TECHNICAL REVIEW연구자용 상세 해설

이 논문을 읽는 기준: RoboSeed는 단일 신경망 아키텍처가 아닌 model-choice 방법론입니다. Figure1의 5차원 평가 흐름, Figure2의 로컬 ABot-M0 기술구성을 분리해 읽고, Table4의 실제 성공/비용과 Table26의 미완료 aggregate를 함께 봅니다. PDF 원본 크롭의 공간 범위는 아직 수동 검수 대기라고 명시합니다.

01 / 문제 정의

연구가 풀려는 문제

로봇 연구실에 GPU 200시간밖에 없다면 성공률 85.5%짜리 4B 모델과 80.6%짜리 0.8B 모델 중 무엇을 선택해야 할까요? 더 큰 모델이 좋아 보이지만 downstream 적응 학습 비용, 실제 로봇에서의 p95 응답, 프롬프트 형태, benchmark 일치 여부가 빠져 있으면 선택이 불가능합니다. 기존 VLA 논문들의 성공률 표는 서로 다른 학습 시연·액션 정규화·언어 지시·평가 에피소드 수를 혼합하기 쉽습니다. (원문 §1–3)

02 / 핵심 기여

핵심 아이디어

RoboSeed는 모델을 다섯 축으로 표현합니다. P=capability(폐루프 결과), T=training affordability(학습 자원), D=deployment affordability(서빙 비용), V=locally verified research value(검증된 연구상 가치), R=reproduction evidence(재현 근거). 축별로 정해진 anchor를 사용해 0~100 프로파일로 변환하고, balanced·training-constrained·deployment-constrained의 3가지 preference weight를 제공합니다. 그러나 필요한 원시 측정이 빠지면 축 값을 만들지 않으며, 종합 점수도 '-'로 남깁니다. (원문 §5, Table26)

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

일반적인 공개 leaderboard는 한 벤치마크의 최고 성공률을 제시하지만, RoboSeed는 정책 선택에 쓸 수 있는 실험 증거의 질과 비용을 모델별로 남깁니다. 리더보드 지표를 대체하는 새 통합 벤치마크라기보다 프로토콜 일치 여부와 미측정 영역을 공개하는 decision framework입니다. RoboTwin의 동일 ABot 레시피 비교가 다른 native-policy 인터페이스로 전이된다는 주장에는 근거가 없으며, 저자도 종합 등수 제시를 보류합니다.

03 / 설계와 학습

방법론 · 아키텍처

먼저 연구자가 평가할 태스크와 언어·visual goal 계약을 정합니다. 데이터/액션 state dimension과 normalization, 평가 seed, 성공 판정 방식을 맞춰 비교 가능성을 확인합니다. ABot-M0 실험은 RoboTwin의 50 tasks × 각 Clean/Randomized 100 episodes로, 같은 training recipe(150k updates, global batch64, seed42, 4 H200 GPU)를 사용하며 VLM 백본 6개를 교체합니다. 얻은 성공률과 GPU-hours는 같은 구성의 비교에 한정합니다. 이후 별도 실험 및 공개 문서에서 연구 증거를 수집해 다섯 축에 매핑하고, 입력이 부족한 모델의 aggregate는 계산하지 않습니다. (PDF §3–5, Table4, Appendix)

DEEP DIVE / 01

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    결정 문제와 적용 인터페이스 정의

    제어 지시가 언어 텍스트인지, 시각 목표인지, action state dimension이 무엇인지 먼저 명시합니다. 이는 두 모델이 같은 LIBERO나 RoboTwin 점수를 보고했어도 직접 대조할 수 있는지 판정하는 선행 조건입니다.

    task + sensor/action contract + constraint
  2. 02

    동일 레시피에서 백본 비용–성공률 측정

    ABot-M0의 action expert와 geometric pathway를 고정하고 다양한 Qwen 백본을 사용합니다. RoboTwin의 50개 과제, clean/randomized 각각 100 episodes로 총 각 장면 유형 5000회 결과를 수집하고, 150k updates와 글로벌 batch64를 유지합니다.

    checkpoint → 2×5000 rollouts + GPU-hour trace
  3. 03

    모델별 증거와 출처 감사

    성공률 외에 training GPU-hours, model/peak VRAM, action-prediction p95, 코드·seed·레시피 공개 여부, 재현 가능한 실패 조건을 검토합니다. native instruction의 차이가 있는 타 계열 정책은 결과를 하나의 실험으로 합산하지 않습니다.

    native measurements + provenance → evidence matrix
  4. 04

    5차원 점수와 선호 프로파일 적용

    P/T/D/V/R 각 차원의 측정에 anchor를 적용합니다. balanced, training constrained, deployment constrained preference weights는 가치를 정하는 입력일 뿐 저자가 훈련된 ranker나 정확한 미래 성능 예측기를 제안한 것은 아닙니다.

    supported dimensions × anchored 0–100 scores
  5. 05

    누락된 측정값은 빈칸 유지

    배포 95번째 백분위 지연 등이 누락되면 필수 차원으로 합산할 근거가 없으므로 aggregate '-'를 남기고 관찰된 가중 입력 커버리지를 보여줍니다. 이후 어떤 측정을 해야 의사결정할 수 있는지도 기록합니다.

    score only with complete inputs; else coverage report
DEEP DIVE / 02

핵심 설계·학습 신호 해설

Benchmark 비교 가능성 게이트

원시 스코어가 같아도 task list, visual prompt contract, action de-normalization, episode cap, evaluator commit 등이 다르면 비교는 엄격히 제한됩니다. 저자는 RoboTwin 내 공통 recipe 학습과 타 모델의 native setup 평가를 분리합니다. 단위가 맞지 않는 외부 성능은 조건을 남긴 참고치입니다.

읽기 포인트시드 42로 학습한 로컬 체크포인트와 공식 발표 체크포인트는 동일 모델군이어도 같은 결과가 아닙니다.

성공률 대 비용의 파레토 관계

Table4에서 Qwen3-VL-4B(85.52%,288.1 GPU-hours)와 Qwen3.5-2B(84.12%,212.9 GPU-hours)는 비용 대비 선택이 달라질 수 있습니다. Qwen3.5-9B 509.2 GPU-hours는 평가 성공률 83.83%로 백본 크기만 늘리는 전략이 충분조건이 아닙니다.

읽기 포인트GPU-hour는 특정 H200 환경의 비용지표로 cloud dollar나 에너지 소비가 아닙니다.

규칙 기반 5차원 평가와 중간값 대치 금지

일반 보고서처럼 빠진 serving latency에 평균값을 넣어 1등을 정하지 않습니다. §5의 weight를 바꾸면 같은 원시 결과라도 다른 선택이 가능하며, Table26에서 aggregate '-'는 오류가 아니라 증거 부족의 명시적 신호입니다.

읽기 포인트coverage 84%는 성공률이나 모델점수 84점이 아닙니다.

ABot-M0의 실제 모듈은 별도

PDF Figure2는 다섯 평가 축의 가중치 그림이 아니라, ABot-M0에서 VLM에 VGGT geometry stream을 결합하고 action expert로 흐르는 기술적 module 관계를 설명합니다. 이 사실을 Figure1의 RoboSeed 전체 평가 프로그램과 구분해 잘못된 캡션을 방지했습니다.

읽기 포인트Figure2는 PDF 자동 crop이므로 패널 범위의 수동 검수가 필요합니다.

05 / 비판적 해석

한계와 비판적 검토

RoboSeed는 동일 backbone family/recipe의 탐색과 서로 다른 native interface를 가진 타 모델의 연구가치 평가를 구별합니다. 공개 Leaderboard의 다른 GPU·예산·action normalization을 억지로 같은 조건이라고 가정할 수 없습니다. 일부 서빙 trace/p95 latency가 빠져 5차원 합산 점수를 생성하지 않았고, Table26은 오히려 비교를 미룬 근거입니다. 백본별 1회 학습 seed42의 점 추정과 Clean/Randomized 장면은 무작위 OOD 세계 전체에 대한 일반화 보증이 아닙니다. (원문 §3–5, §6, Appendix)

RESEARCH LAB / EDITORIAL PROPOSAL

내 연구에 적용한다면?

아래는 논문 저자의 검증 결과가 아니라, 논문에서 출발해 설계한 **후속 실험 제안**입니다.

검증 가설

성공률 1–2%p 손실을 허용할 때 저예산 사용자에게 적합한 checkpoint는 다른 조건에서의 최대 성공률 모델과 달라질 수 있으나 serving p95가 누락되면 최종 선택이 바뀔 수 있습니다.

구체적 실험 설계

ABot-M0 backbone 6개를 동일 RoboTwin 50 tasks × 100 episodes × clean/randomized에서 반복 재훈련(각 3 seeds), 동일 evaluator commit 13c3c47과 150k updates/global batch64를 사용합니다. H200 GPU-hour, p95 latency, VRAM 및 실물 로봇 제어 loop 지연을 독립 계측합니다.

비교군·Ablation

Qwen3.5-0.8B, Qwen3-VL-2B/4B, Qwen3.5-2B/4B/9B within ABot; OpenWAM/LiLa only with explicitly harmonized interface; balanced/training-constrained/deployment-constrained rank sensitivity.

기록할 지표

strict task success/clean/randomized, GPU-hours and energy kWh, p50/p95 serving latency, memory, evidence-completeness coverage, seed variance, rank stability under score anchors.

실패 해석·주의점

다른 행동 인터페이스를 강제로 통일하면 원래 정책의 장점을 훼손할 수 있습니다. 빈 latency/VRAM 값을 0이나 중간 점수로 채워 최종 1등을 만들면 안 됩니다.

07 / ABSTRACT & PROVENANCE

원문 / 출처 확인

편집자가 작성한 초록 기반 한국어 요약이며 공식 영문 초록의 원문/번역이 아닙니다.

RoboSeed는 성능만으로 VLA/WAM을 순위화하면 GPU 예산, 제어 인터페이스, 서비스 지연, 근거 공개 수준을 놓친다고 지적합니다. ABot-M0 백본의 고정된 RoboTwin 평가와 다양한 모델의 원시 측정치를 분리하고, 결측값을 보간하지 않은 5차원 평가 프로파일과 조건부 의사결정을 제안합니다.

해설은 논문 저자들의 진술과 편집자의 비판적 질문을 구분합니다. 특정 지표·인과관계·재현성을 판단할 때는 반드시 원문의 실험 설정을 확인해 주세요.
