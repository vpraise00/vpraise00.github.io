AR-WAM: A Visual-Conditioned Agent-Ready World Action Model for Robotic Manipulation

AR-WAM은 상위 AI 에이전트와 로봇 정책 사이의 언어 중복을 없애고, bounding box+operation token으로 원자 skill을 실행하는 0.5B latent World-Action Model입니다. RoboTwin 2.0의 clean/randomized·RMBench 기억 과제·실물 Astribot S1, 구성요소 ablation과 4090 지연을 PDF Table I–VI로 대조합니다.

00 / ONE-MINUTE RECAP

핵심을 먼저 읽기

AI 에이전트가 이미 지시를 이해했다면 하위 로봇 정책이 다시 자연어를 처리해야 할까요? AR-WAM은 목표 객체 bbox와 원자적 operation token만을 정책 입력으로 넘기고, 에이전트가 기억·재시도·작업 분해를 담당하게 합니다. (PDF §I–III)

⌁ DEEP TECHNICAL REVIEW연구자용 상세 해설

핵심 주장과 검증 경계: 이 논문은 거대한 언어모델을 소형 모델로 압축했다는 이야기보다, 상위 agent와 실행 policy 사이에서 의도/대상/행동을 어떤 인터페이스로 전달해야 하는가를 실험합니다. PDF Figure1의 구성요소를 읽고, Table I(로봇 조작), II–III(ablation), IV(에이전트 기억), V(실물), VI(추론 지연)을 서로 다른 평가로 분리합니다.

01 / 문제 정의

연구가 풀려는 문제

두 개의 비슷한 흰 병이 놓인 책상에서 '오른쪽 병을 두 번 들어 주세요'라는 지시를 받는다고 가정하겠습니다. 상위 에이전트는 사진으로 어떤 병인지 알았어도, 하위 VLA에 다시 문장으로 전달하면 물체 참조가 불분명해지거나 이미 수행한 자연어 이해를 중복합니다. 또한 집기 실패 시 무엇이 잘못됐는지(에이전트의 의도인지 로봇의 운동 실행인지) 구분하기 어렵습니다. 기존 거대 VLA/WAM의 언어 조건이 상위 agent와 저수준 정책 사이의 병목이 되는지 문제를 제기합니다.

02 / 핵심 기여

핵심 아이디어

에이전트는 '저 병'의 픽셀 bounding box g와 '집기' 같은 학습형 skill token s를 제공합니다. 하위 로봇은 bbox로 목표 물체를 식별하고 operation token으로 수행할 조작 유형을 선택하며, 0.5B 세계-행동모델이 현 영상·proprioception에서 action chunk를 생성합니다. 결과를 query로 다시 살펴 실패라면 상위 에이전트가 재계획·재실행합니다. Figure 1은 reasoning head, future gist, action expert를 함께 보여주며 Figure 2는 실제로 실패가 일어났을 때 재시도하는 agent-policy loop입니다.

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

π0.5나 X-VLA는 보통 시각·언어 지시를 VLA에 입력하는 반면 AR-WAM은 의미 해석/기억을 상위 agent가 하고 하위 policy는 target bbox와 discrete atomic skill만 사용합니다. Fast-WAM과 LiLa-WAM처럼 latent future target을 쓰되, explicit reasoning target 및 detect/execute/query API를 통합합니다. TableI clean에서는 Fast-WAM이 앞서고 TableIV M(1)에서는 Cortex가 앞서므로 '전 과제 절대 최고' 주장은 틀립니다.

03 / 설계와 학습

방법론 · 아키텍처

0.5B는 동결된 DINOv3 비전 인코더 약 0.3B와 0.2B Transformer를 합친 규모입니다. Reasoning expert와 World Action Expert가 transformer를 공유하며, 작은 bbox-embedding 및 skill embedding이 AdaLN conditional modulation으로 통합됩니다. Reasoning head는 대상 mask, 양팔 end-effector 목표, task abstract를 감독합니다. 보조 foresight-gist extractor는 관측 두 시점에서 학습 목표를 만들어 주지만, 추론 시 미래 정답 영상을 요구하지 않습니다. Action expert는 action/foresight/reasoning gist를 flow matching 기반으로 학습하고 KV cache를 재사용합니다. detect·execute·query는 에이전트의 인터페이스이며 homing 등 보조 이동은 별도 고전적 계획기로 처리합니다. (PDF §III, Figure 1)

DEEP DIVE / 01

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    01. 에이전트가 자연어를 해석하고 목표 객체 선택

    상위 VLM agent는 사용자의 작업을 원자 skill로 분해한 뒤 현재 RGB 관측의 대상 bbox와 pick/place/click/handover 같은 operation token을 지정합니다. Spatial grounding이 완벽하다거나 로봇이 원문 텍스트를 재처리한다는 뜻은 아닙니다. (PDF §III-A/E)

    agent: language+history → target bbox g + operation s
  2. 02

    02. 고정 DINOv3로 시각 표현과 목표 조건 구성

    관측 이미지는 동결 0.3B DINOv3로 인코딩합니다. bbox는 경량 MLP로 embedding이 되고 operation·actor/arm·style condition과 결합해 AdaLN으로 transformer에 주입됩니다. 고정 비전 인코더와 실행 정책을 구별합니다. (PDF §III-B, Figure 1)

    RGB + bbox + skill + proprioception → condition tokens
  3. 03

    03. Reasoning expert: 정답 감독이 있는 의도 중간출력

    Shared 0.2B transformer 안의 reasoning expert는 목적 객체 mask, 양팔 종료 pose, one-hot task abstract를 예측하도록 훈련받습니다. 이는 inference에서 매번 LLM text thought를 생성하는 것이 아니라 시각적 의도와 조작 목표를 감독하기 위한 조건 출력입니다. (§III-B)

    object mask + end-effector target + task abstract
  4. 04

    04. Latent foresight gist를 보조 목표로 학습

    시연의 시간적으로 떨어진 두 RGB 프레임을 frozen visual encoder와 offline future-gist model로 압축해 future state가 어떻게 변화하는지 학습 목표를 구성합니다. Future gist는 예측할 latent target이지 미래를 실제 관측하거나 test-time video diffusion을 돌리는 것이 아닙니다. (Figure 1, §III-B/C)

    observed demonstration future → compact training target
  5. 05

    05. World Action Expert가 action chunk를 flow matching

    현재 상태와 입력 조건, noisy action, reasoning/foresight latent guidance를 공유 transformer가 함께 처리해 action chunk를 denoise합니다. Reasoning expert의 KV cache를 활용해 반복 ODE 단계에서 조건 부분의 중복 연산을 줄입니다. (PDF §III-C, Figure 1)

    noisy action → multi-step denoising → motion action chunk
  6. 06

    06. detect·execute·query로 메모리와 실패 복구 분리

    상위 agent는 실행 이후 대상 위치와 결과를 다시 질의하여 기억 상태를 갱신합니다. 집기가 실패하거나 물체를 떨어뜨리면 Figure 2처럼 현재 관측에서 새 bbox와 skill을 지정해 재시도합니다. 필요시 homing은 classical planning; learned action policy 성능과 다른 시스템 구성요소입니다. (§III-E, Figure 2)

    observe → detect → execute → query → replan / retry
  7. 07

    07. 평가: agent-independent / agent-dependent / real robot 구분

    RoboTwin 2.0에서는 state-machine expert와 검출기로 상위 agent 변동을 통제합니다. RMBench에서는 Kimi-K3/Qwen3.8-27B의 memory reasoning이 성능에 영향을 줍니다. Astribot S1은 실제 demo 100개/task post-training 후 평가합니다. 이 셋의 성공률은 다른 정의입니다. (§IV-A–E)

    simulation clean/randomized → RMBench memory → S1 20-trial real eval
DEEP DIVE / 02

핵심 설계·학습 신호 해설

Text condition 대비 bounding box 효과

Table II Text-only 모델 평균74.2%와 VP 모델87.2%는 같은 학습 스케줄의 RoboTwin 시험이며 -13.0%p 차이입니다. 그러나 bbox 생성기의 오류가 실제 배포 성능에 그대로 들어갈 수 있으므로 '텍스트는 모든 로봇에서 필요 없다'가 아닙니다.

읽기 포인트Detection confidence·oracle bbox 조건을 별도 ablation으로 나눕니다.

Reasoning head가 학습하는 정보

Target mask는 bbox보다 정밀한 객체 영역, end-effector target pose는 양팔 실행 목표, task abstract는 skill 상태를 감독합니다. 학습한 내부 의도가 실제 행동의 원인인지 확인하려면 제거 ablation 및 오류 사례를 같이 봐야 합니다.

읽기 포인트Table II w/o reasoning 79.4 vs full 87.2, 같은 지표 단위임을 확인.

Future gist를 patch로 대체하면 왜 나빠지나

Future patch target은 시각적 상세 정보와 운동에 불필요한 variation까지 학습하므로 TableII에서 76.4%, 미래 gist는87.2%로 차이납니다. 시각화가 더 선명해서 제어가 더 좋은 건 아니며 inference-time 미래 정답이 필요한 방식도 아닙니다.

읽기 포인트Figure1의 offline gist extraction 부분과 테스트 추론 경로를 구분합니다.

AdaLN과 cross-attention의 속성 차이

Table III(b)의 AdaLN87.2%, Cross73.4%, 파라미터0.50B 대0.44B. 논문은 condition perturbation 감도 분석을 함께 제시하지만 용량·토큰 경로가 달라 학습 예산을 추가 통제할 필요가 있습니다.

읽기 포인트proprioception shortcut에 대한 sensitivity를 입력 변경량/동일 random seed로 비교합니다.

Long-horizon memory는 하위 정책이 아닌 agent의 책임

RMBench M(n)에서 Kimi 52.5/Qwen63.5 vs Goal2Skill38.7%인 반면 M(1)은 Cortex75.2%가 더 좋습니다. Agent 모델과 detector의 차이가 생길 수 있으므로 0.5B 자체의 memory 능력이라고 서술해서는 안 됩니다.

읽기 포인트두 에이전트의 prompt/grounding/detect 조건을 고정한 실험을 제안합니다.

05 / 비판적 해석

한계와 비판적 검토

물체 bbox가 틀리거나 작은 물체가 겹치면 정책의 semantic condition도 틀리며, RMBench M(1)에서는 메모리강화 Cortex의 75.2%보다 Kimi 71.2%로 낮습니다. 'Swap T'에서도 개선이 없고, 조작 어휘는 케이블 끼우기 등 세밀한 접촉에 부족합니다. 실제 로봇은 시뮬레이션 정책을 100 시연/과제 추가 미세조정했으므로 zero-shot sim2real 아님을 분명히 합니다. 14.09ms는 agent detector·API 지연·로봇 운동 시간 미포함이며, AdaLN 대 cross-attention 비교는 파라미터 수(0.50B/0.44B)가 달라 순수 동일용량 causal test가 아닙니다.

RESEARCH LAB / EDITORIAL PROPOSAL

내 연구에 적용한다면?

아래는 논문 저자의 검증 결과가 아니라, 논문에서 출발해 설계한 **후속 실험 제안**입니다.

검증 가설

동일 policy 크기·시연·비전 인코더를 사용할 때 bbox+operation condition과 gist supervision이 다중 객체 선택·반복 조작에서 자연어 조건 대비 강건하지만 detector 오차가 증가하면 장점이 줄어듭니다.

구체적 실험 설계

RoboTwin2.0에서 논문 10 tasks clean/random 50 trials/setting을 3 random seeds로 재실행하고 동일 초기상태, demo 50 clean+500 random/task 및 agent state-machine을 고정합니다. 실물 S1은 100 expert demos/task fine-tune, 20 trials/task와 안전 중단 규칙을 유지합니다.

비교군·Ablation

VP+Gist+Reasoning, Text+Gist, VP w/o reasoning, VP w/o foresight, VP+future patch, VP+oracle bbox, VP+detector jitter; AdaLN vs Cross parameter-matched control.

기록할 지표

task strict success 및 confidence intervals, bbox IoU/target selection errors, retry counts, agent API token usage, p50/p95 full-loop latency, 4090 chunk latency, homing time.

실패 해석·주의점

agent detector의 품질이 정책에 귀속될 수 있으며 RoboTwin clean/real robot 결과는 직접 합산할 수 없습니다. 같은 model capacity와 추론 조건 통제 없이 AdaLN 우월성을 단정하지 않습니다.
