SmolVLA: A Vision-Language-Action Model for Affordable and Efficient Robotics

SmolVLA는 작은 VLM을 단순 축소하는 대신 영상 토큰·Transformer 층·action expert의 계산량을 분리해 0.45B VLA로 실제 SO100/101 조작까지 실험한다. 특히 비동기 실행의 처리량 개선과 성공률 감소를 함께 읽어야 한다.

01 / 문제 정의

연구가 풀려는 문제

실제 저가형 SO100/SO101은 몇 초짜리 pick-and-place에도 시야가 계속 변한다. 수십억 파라미터의 VLA가 매 관측마다 큰 VLM을 호출하면 로봇이 행동을 멈추거나 GPU가 부족해진다. 반대로 단일 과제 imitation policy는 새로운 물체와 언어 지시를 충분히 전이하지 못한다. 논문은 '모델 용량을 작게 유지하면서 로봇 행동을 어느 수준까지 재사용할 수 있으며, 모델이 다음 행동 묶음을 계산하는 동안 로봇을 멈추지 않을 수 있는가?'를 묻는다. (원문 §1, §3)

02 / 핵심 기여

핵심 아이디어

핵심 직관은 '무엇을 보고 있는가'와 '모터가 어떻게 움직이는가'의 계산을 분리하는 것이다. 영상 해석용 SmolVLM2의 후반 Transformer를 제거해 초기 특징만 행동 전문가에 전달하고, 미래 n개 동작은 조건부 flow matching으로 생성한다. 카메라 프레임을 64개 비주얼 토큰으로 줄여 시퀀스 길이를 억제한다. 현장에서 큐에 남은 동작이 충분할 때 다음 관측을 보내 새 chunk를 미리 받아두는 방식은 '설거지 접시를 옮기는 동안 다음 접시를 미리 보는 조수'에 비유할 수 있다. 이 설계는 상위 언어 추론을 전부 유지하는 범용 로봇 추론기와 다르다. (Figure 1·2, §3.1–3.3)

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

OpenVLA와 π0가 큰 VLM의 행동 예측 능력을 늘렸다면 SmolVLA는 초기에 충분한 특징만 읽는 경량화와 별도 행동 전문가를 택한다. ACT가 저가 팔에서 좋은 단일 작업 기준점인 반면 이 모델은 공개 커뮤니티 데이터로 pretrain한 후 multitask fine-tune을 검증한다. 다만 Table 3의 ACT single-task vs SmolVLA multi-task 결과를 구조만의 인과효과로 해석하면 안 된다. Figure 5는 과업 성공률뿐 아니라 로봇이 멈춰 있는 시간과 정해진 시간 내 완료 횟수를 보고하도록 평가 관점을 확장한다.

03 / 설계와 학습

방법론 · 아키텍처

입력은 다중 RGB 영상, 자연어, 로봇 proprioception이다. SigLIP 시각 인코더와 SmolLM2 언어 경로를 가진 SmolVLM2의 일부 층을 이용하며 image tiling 생략과 pixel shuffle로 각 영상의 시각 토큰 수를 낮춘다. 로봇 상태는 projection을 통해 조건 토큰으로 넣고, action expert는 VLM 토큰을 향한 cross-attention과 액션 내부 causal self-attention을 교차 적용한다. 학습은 실제 action chunk에 노이즈를 섞고 연속시간 velocity를 회귀하는 conditional flow-matching 목적이다. 추론은 노이즈 action을 적분해 chunk를 만들고, RobotClient가 앞선 chunk를 실행하는 동안 PolicyServer가 새 chunk를 비동기로 계산한다. 남은 액션 비율 임계값과 관측 중복 제거는 Algorithm 1에 명시돼 있다. (Figure 1·2, §3)

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    입력 표준화: 영상·언어·상태

    여러 RGB 카메라 관측을 image encoder에, 명령을 text tokenizer에, 관절·그리퍼 등의 수치 상태를 state projector에 넣는다. 고정 길이 작업 목표가 아니라 현재 시점 관측과 행동 구간을 짝지어 학습한다.

    o_t=(RGB, language, robot state)
  2. 02

    시각 토큰 압축

    SmolVLM2의 SigLIP 비전 특징을 쓰되 image tiling을 제거하고 pixel shuffle로 영상 한 장당 토큰을 64개로 줄인다. 계산량을 크게 낮추지만 작은 물체 인식과 부분 가림에서 손해를 볼 수 있어 별도 평가가 필요하다.

    image → 64 visual tokens
  3. 03

    상위 VLM 블록 자르기

    SmolLM2 기반 VLM의 깊이 L 중 초기 N층만 남긴다. 질문응답용 최종 decoder 층 전체가 필요한지보다 행동 조건을 만들 만큼의 공간·의미 특징이 있는지에 집중한다. 원문 Table 8은 N 변화와 성능을 별도로 테스트한다.

    VLM early-layer representation
  4. 04

    Flow Matching 행동 전문가 학습

    정답 action chunk와 가우시안 노이즈를 중간 시간점에서 섞고 목표 velocity를 회귀한다. Action Expert는 VLM 특징을 참고하는 cross-attention과 토큰 순서를 보존하는 causal self-attention을 교차 사용한다.

    (noise action, VLM context, t) → velocity
  5. 05

    한 번의 정책 호출로 행동 묶음 생성

    추론에서 velocity field를 적분해 미래 n개 저수준 동작을 내고 action queue에 넣는다. 이는 언어 토큰을 1개씩 출력하는 VLA와 달리 연속 제어 묶음의 생성이다.

    π(o_t) → [a_t,…,a_t+n]
  6. 06

    RobotClient–PolicyServer 비동기 제어

    클라이언트가 기존 행동을 소비하다 남은 비율이 g 이하이면 새 관측을 서버로 보낸다. 유사한 상태를 걸러 중복 호출을 줄이고 새 chunk를 수신하면 겹침을 조정한다; 응답이 늦으면 기존 큐를 계속 소비한다. (Figure 2, Algorithm 1)

    queue depth, observation age, server latency

핵심 설계·학습 신호 해설

VLM과 action expert의 서로 다른 역할

VLM의 초기 블록에서 RGB·텍스트·상태를 합쳐 조건 특징을 만들고, action expert는 시계열 행동 자체의 생성에 집중한다. 범용 VLM 전체를 거대 action generator와 끝까지 공동 계산하지 않아도 된다는 점이 경량화의 핵심이다.

읽기 포인트Figure 1의 가위 아이콘·cross-attention 연결을 실제 저자 이미지로 확인

Causal SA와 CA를 왜 섞는가?

CA-only는 행동 후보끼리 충분히 상호작용하지 않고, SA-only는 언어·영상 맥락 사용이 제한된다. Table 6에서 CA79.0, SA74.5, CA+SA85.5; Table 7에서 causal74.5가 bidirectional67.5를 웃돈다. 이는 별도 통제 ablation의 LIBERO 평균이다.

읽기 포인트Table 6의 85.5를 최종 Table 2의 87.3과 혼합하지 말기

비동기 큐는 '동작의 공백'을 줄인다

서버 추론이 끝날 때까지 정지하는 sync 방식과 달리, async 방식은 직전 chunk의 남은 액션을 쓰는 동안 새 영상을 계산한다. queue threshold g, joint-space similarity filter, 네트워크 지연이 안정성 변수다. (Algorithm 1)

05 / 비판적 해석

한계와 비판적 검토

Table 3의 저가 팔 실험을 다른 자유도·로봇 보행에 그대로 확장할 수 없다. 본 논문의 community pretraining은 주로 SO100 단일 embodiment의 22.9K 정도 시연이므로 진정한 기구학적 zero-shot 이식 근거가 약하다(§5.1). 비동기 모드에서는 이전 관측 기반 동작을 잠시 더 실행하므로 접촉 위험·충돌률·네트워크 꼬리 지연을 추가 측정해야 한다. 논문의 실물 SO100 성공 판정은 단계별 부분 점수를 포함할 수 있어 일괄적인 완전 성공과 구분한다. Ablation Table 6–9는 별도 VLM 동결/처음부터 학습 설정이어서 사전학습 완료한 최종 Table 2 수치와 직접 비교할 수 없다. (원문 §4.7, §5 및 Appendix A)

RESEARCH LAB / EDITORIAL PROPOSAL

내 연구에 적용한다면?

아래는 논문 저자의 검증 결과가 아니라, 논문에서 출발해 설계한 **후속 실험 제안**입니다.

검증 가설

에지 GPU에서 이미지 토큰 압축과 비동기 action queue는 평균 latency를 낮추지만 작은 대상 물체·갑작스러운 가림에는 제어 위험을 증가시킬 수 있다.

구체적 실험 설계

SO100 또는 SO101에서 픽앤플레이스·정렬 각 50시연을 고정하고, 같은 데이터 split·초기 무게·평가 조명·카메라를 쓴다. 시간 동기화가 가능한 로깅으로 관측 캡처→네트워크 전송→모델 추론→모터 커맨드 적용의 타임스탬프를 저장한다.

비교군·Ablation

Full VLM vs half-depth, 64 vs 더 많은 visual tokens, CA-only vs CA+SA, sync vs async, queue threshold g=0.25/0.5/0.75. 각 조합은 동일 데이터·3개 seed와 동일 안전 timeout으로 실행한다.

기록할 지표

10–20개 물체별 strict 완료율과 단계별 부분점수, p50/p95 end-to-end 지연, 평균 관측 나이, 60초 완료개수, contact interruption, actuator jerk, GPU VRAM 및 joule/episode.

실패 해석·주의점

더 빨리 움직여서 60초 완료개수가 커져도 오동작·충돌이 늘 수 있다. 모델이 고속일수록 환경 리셋과 사람 감독을 동일하게 유지하고, 속도와 성공률을 단일 합성 점수로 감추지 않는다.
