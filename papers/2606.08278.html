SIMPLE: Simulation-Based Policy Learning and Evaluation for Humanoid Loco-manipulation

SIMPLE은 휴머노이드 전신 보행·조작을 MuJoCo 접촉 물리와 Isaac Sim 렌더링으로 분리해 평가하는 벤치마크다. 60 설계 과제·50 실내 장면·1,000+ 물체, 9가지 정책의 과제별 10회 성공 횟수, 데이터 생성 ablation과 sim-to-real을 구분해 해설한다.

핵심을 먼저 읽기

SIMPLE의 가치는 모델 승률 하나가 아니라 동일 humanoid dynamics와 시각 randomization을 공유하는 평가 조건, 자동 planning/VR teleop 데이터 수집, sim-to-real gap을 함께 표준화하려는 데 있다. (Figure 2·4, Table 1–5)

01 / 문제 정의

연구가 풀려는 문제

탁자 위 한 개 팔 조작은 LIBERO나 RoboTwin으로 비교하기 쉽지만 휴머노이드는 물건에 손을 뻗는 순간 균형을 잡아야 하고, 보행·회전·양팔 접촉까지 합쳐야 한다. 다른 연구가 실제 로봇에서 제각각 촬영 조건·작업·리셋 기준으로 성공률을 보고하면 Ψ0와 DreamZero 중 어떤 정책이 강한지 재현하기 어렵다. 순수 보행 benchmark는 손의 조작을, tabletop benchmark는 전신 균형과 이동을 놓친다. 따라서 '하나의 시뮬레이터에서 광학적 다양성과 접촉 dynamics를 모두 확보하고 실물 성적을 어느 정도 예측할 수 있는가?'가 문제다. (§1–2)

02 / 핵심 기여

핵심 아이디어

핵심은 물리와 영상의 '역할 분리'다. MuJoCo는 접촉·기구학·전체 균형의 정답 상태를 계산하고 Isaac Sim은 같은 상태로 사실적인 카메라 관측을 만들어낸다. 사람은 PICO XR에서 시연하거나 motion planning으로 trajectories를 대량 생산한다. 로봇 정책은 동일 Gym 인터페이스에서 난도별 세 조건(표 L0/L1/L2)의 영상·상태를 보고 액션을 출력한다. 예컨대 탁자 밑으로 몸을 굽혀 상자를 집는 작업은 단순 집기보다 보행 안정·허리 굽힘·두 손의 역할을 동시에 요구한다. (Figure 2, Figure 4)

DEEP DIVE / 04

기존 연구와 무엇이 다른가?

LIBERO·RoboTwin은 주로 고정형 조작 팔 정책의 학습·평가를 위해 만들어졌다. HumanoidBench 등 보행/전신 실험은 있더라도 복잡한 물체·시각적 domain randomization·실물 행동 시연 처리의 표준 인터페이스가 균일하지 않았다. SIMPLE은 MuJoCo dynamics와 Isaac Sim rendering을 결합해 동일한 실험 난이도를 제공한다. Ψ0, π0.5, GR00T N1.6, DreamZero를 비롯해 DP·ACT를 공통 프로토콜에서 비교하는 데 연구 가치가 있다. 특정 모델이 전체 과제에서 압도적이라는 결론이 아니라, 어떤 제어/접촉 패턴에서 어느 모델이 실패하는지 더 공정하게 드러내는 벤치마크다.

03 / 설계와 학습

방법론 · 아키텍처

Data generation에서는 (A) 물체를 MuJoCo에 떨어뜨려 안정 pose를 얻고 BoDex로 grasp를 고르고 cuRobo로 양팔 경로를 만든 뒤 하체 motion controller가 이동을 맡거나, (B) PICO VR의 손동작을 IK로 옮겨 operator가 원격 조종한다. 검증된 trajectory는 Isaac Sim에서 장면·재질·조명·카메라·물체 pose를 바꾸며 재생하여 photorealistic image와 상태가 함께 있는 dataset으로 보존한다. 테스트에서는 MuJoCo step마다 robot state를 Isaac Sim에 동기화하고 이미지·proprioception을 정책에 넣어 whole-body tracker로 행동을 실행한다. (Figure 2,4,7; §3 및 부록)

DEEP DIVE / 01

모델 구조와 처리 흐름

개념적 처리 순서를 정리한 편집 다이어그램이며 원논문의 그림을 복제한 것은 아닙니다.

  1. 01

    작업·객체 구성

    60가지 설계 whole-body 과제를 50개 실내 장면과 1,000개 이상의 asset에서 조합한다. 단순 grasp, 허리 굽힘, 이동 pick-place, handover 등 과제 난도가 제각각이다.

    task + scene + initial object states
  2. 02

    MuJoCo에서 접촉 dynamics 계산

    중심 동역학 시뮬레이터는 MuJoCo다. 손·물체 접촉과 보행 균형을 같은 state에서 다루고 정책의 joint target 및 whole-body tracking으로 한 스텝 전진한다.

    physics state s_t → s_t+1
  3. 03

    데이터 생성 경로 A: 자동 motion planning

    안정 pose로 놓인 물체에 대해 BoDex grasp를 생성·필터링하고 cuRobo dual-arm 경로를 구성한다. 이동은 scripted lower-body 경로가 맡아 upper-body 계획과 동기화한다. (Figure 4·7)

    grasp DB → arm path + base locomotion
  4. 04

    데이터 생성 경로 B: VR teleoperation

    PICO에서 받은 양손 동작은 inverse kinematics로 로봇 목표가 되고, 실시간 whole-body tracking policy가 동작 중 균형과 이동 제어를 보완한다. 로봇 본체에 직접 사람이 올라타는 방식이 아니다.

    operator hand pose → IK → whole body action
  5. 05

    Isaac Sim의 Offline replay/render

    물리 시연 궤적을 Isaac Sim에서 재생하고 카메라 각도·재질·조명·배경·물체 위치를 randomize한다. 시각의 변화를 과제 성공 physics와 분리하여 다중 조건 이미지를 얻는다. (Figure 2)

    MuJoCo trajectory → photoreal RGB
  6. 06

    정책 평가: 동일 Gym loop

    각 step에서 MuJoCo state를 Isaac Sim에 동기화, 렌더링 관측을 생성해 VLA/WAM/ACT/DP 등에 공급하고 실행한다. 테이블 성공 수는 L0/L1/L2 각 10 rollout의 성공 횟수다.

    obs → policy → action → physics → render
  7. 07

    Sim-to-real 전이 검증

    SIMPLE 데이터만으로 미세조정한 Ψ0 정책을 실물 humanoid에서 추가 real fine-tuning 없이 실행한다. 시뮬레이션과 실제의 동작 분포가 비슷한 제한된 태스크에서 비교한다.

    paired sim and real rollouts
DEEP DIVE / 02

핵심 설계·학습 신호 해설

두 개의 시뮬레이터, 하나의 물리적 정답

MuJoCo를 고주파 제어의 단일 physics source로 사용하고 Isaac Sim은 렌더링을 제공한다. 렌더링 장면을 바꿔도 dynamics 통제가 유지되는 대신, 광학과 실제 접촉의 domain gap은 별도로 남는다.

읽기 포인트Figure 2의 MuJoCo/IsaacSim 데이터 이동 방향 확인

Motion planning만으로 모든 데이터가 만들어지는가?

아니다. 자동 경로는 object grasp/kinematic clearance에 강하지만 복잡한 휴머노이드 행동의 텔레오퍼레이션 시연은 다른 운동 다양성을 포함한다. Table 4에서 MP-only 평균 성공 횟수 5.00과 teleop-only 7.56 차이는 그 학습 분포의 중요성을 드러낸다.

난도 L0/L1/L2의 평가 의미

05 / 비판적 해석

한계와 비판적 검토

60 tasks와 '논문 실험에서 공개된 6개 대표 작업의 표'를 혼동하면 안 된다. 전체 60과제를 각 정책이 모두 평가한 것은 아니다. 본문의 randomization 설명(Level 1–3)과 그림/표의 L0–L2 표기에는 명명 차이가 있어 실험값은 실제 Table1 L0/L1/L2로 기록한다. 평가 성공은 시뮬 리셋·자산·추적 정책·물리 설정에 의존하며 현실 오차가 남는다. Appendix에서는 일부 joint tuning과 16 task subset을 별도 평가한다. 원문은 photorealistic Isaac Sim rendering의 속도 한계 및 rigid-object 중심의 실험을 인정하므로 deformable cloth, 계단 이동, 센서 지연·고장까지 실물 보증을 주지 않는다.

RESEARCH LAB / EDITORIAL PROPOSAL

내 연구에 적용한다면?

아래는 논문 저자의 검증 결과가 아니라, 논문에서 출발해 설계한 **후속 실험 제안**입니다.

검증 가설

SIMPLE의 난도별 domain randomization은 단순한 배경 변화보다 접촉 위치 및 보행–팔 협응이 필요할 때 성능에 큰 영향을 미친다.

구체적 실험 설계

GitHub SIMPLE 공식 코드를 고정 commit/Isaac Sim/MuJoCo 버전으로 재현해 XMovePick, BendPick, XMoveBendPick 세 과제부터 실행한다. 같은 초기 위치 10개 seed를 각 L0/L1/L2에 고정한다. 전체 60 task 배포가 준비되지 않으면 그 사실을 명시한다.

비교군·Ablation

Ψ0 vs ACT vs DP vs DreamZero (가용 checkpoint 조건에서만); teleop-only vs MP-only, 같은 총 10시연에서 10×L0 vs 5×L0+5×L1, teleop 10 vs100 시연. training steps 2k 고정한 실험과 다른 조건은 별도 표로 분리한다.

기록할 지표

과제별·level별 strict success count/10 및 Wilson CI, 접촉 실패 유형, 중심질량 균형 이탈, 충돌 및 grasp slip, 양팔 경로 길이, GPU FPS, 시연/h, sim-real gap.

실패 해석·주의점

Isaac Sim 라이선스·고성능 렌더링 장치와 humanoid whole-body controller에 따라 재현 비용이 크다. 공개 자산/질량·마찰·실물 센서 alignment가 불일치할 수 있으므로 논문의 60×50 설정을 전부 검증했다고 주장하지 않는다.
